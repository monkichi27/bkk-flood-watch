# BKK Flood Watch — แจ้งเตือนระดับน้ำคลอง / ประตูระบายน้ำ กทม.

ระบบนี้เฝ้าดูระดับน้ำในคลองและประตูระบายน้ำ (ปตร.) ในเขต **ประเวศ สวนหลวง บางกะปิ ลาดพร้าว** (เปลี่ยนเขตได้)
ดึงข้อมูลสดจากสำนักการระบายน้ำ กทม. ทุก 5 นาที แสดงบนแดชบอร์ดแบบแผนที่
**https://monkichi27.github.io/bkk-flood-watch/** และส่งแจ้งเตือนเข้า LINE / Telegram / ntfy / Discord ได้ (ไม่บังคับ)

ลิงก์ "จุดใกล้ที่ทำงาน": เติม `?near=ละติจูด,ลองจิจูด&label=ชื่อ` ท้ายลิงก์ เช่น
`https://monkichi27.github.io/bkk-flood-watch/?near=13.7270,100.6440&label=ออฟฟิศ`
แล้วหน้าเว็บจะโชว์ 5 จุดวัดที่ใกล้ที่สุดไว้ด้านบน (หรือกดปุ่ม "ใช้ตำแหน่งของฉัน")

## อ่านค่าอย่างไร

สีของแต่ละจุดดูจาก **ระยะผิวน้ำถึงตลิ่งฝั่งที่ต่ำกว่า** (ความสูงตลิ่งตามที่ กทม. บันทึกไว้)

| สี | เงื่อนไข (ปรับได้ด้วย `DANGER_FREEBOARD_M` / `WATCH_FREEBOARD_M`) |
|---|---|
| 🔴 ใกล้ล้นตลิ่ง | น้ำห่างตลิ่งไม่ถึง 30 ซม. หรือสูงกว่าตลิ่ง |
| 🟡 เฝ้าระวัง | ห่างตลิ่งไม่ถึง 60 ซม. |
| 🟢 ปกติ | ห่างตลิ่ง 60 ซม. ขึ้นไป |
| ⚪ ไม่มีข้อมูลตลิ่ง / ขัดข้อง | กทม. ไม่มีความสูงตลิ่งที่ใช้ได้ หรือเซนเซอร์ไม่ส่งค่าเกิน 60 นาที |

ทำไมไม่ใช้สถานะ "เตือนภัย/วิกฤต" ของ กทม. เป็นหลัก: เกณฑ์ของ กทม. หลายจุดต่ำกว่าตลิ่งมาก
(เช่น ค.ประเวศฯ-วัดขจรฯ วิกฤต +0.20 ม. แต่ตลิ่ง +2.50 ม.) และบางจุดเป็นค่าตั้งต้น −0.2/0 หรือกรอกเป็นเซนติเมตร
ทำให้วันที่ 28 ก.ย. 69 กทม. ติดป้าย "วิกฤต" ถึง 97 จาก 312 จุด หน้าเว็บจึงแสดงสถานะของ กทม. เป็นข้อมูลประกอบ
และระบุจุดที่เกณฑ์ไม่น่าเชื่อถือไว้ แต่ละจุดยังแสดงแนวโน้ม (ขึ้น/ลงกี่ ซม. ใน 1 ชม.) จากประวัติที่เก็บไว้

ถ้าข้อมูลไม่ได้อัปเดตเกิน 15 นาที (เครื่องที่ดึงข้อมูลปิดอยู่ หรือเว็บ กทม. ล่ม) หน้าเว็บจะขึ้นแถบเตือนสีส้ม

## ที่มา (ก.ย. 2569)

- 26 ก.ย. 69 ฝนตกหนักต่อเนื่อง 48 ชม. บางจุดเกิน 300 มม. กทม. ประกาศเขตภัยพิบัติทั้ง 50 เขต
- จุดที่ต้องจับตา: คลองแสนแสบ (บางกะปิ), คลองประเวศบุรีรมย์ (ลาดกระบัง–ประเวศ–สวนหลวง)
- 27–28 ก.ย. ฝั่งในเมืองเริ่มคลี่คลาย แต่บางกะปิ อ่อนนุช และรามคำแหง ยังน่าห่วง
  ฝั่งตะวันออกต้องพึ่งคลองแสนแสบและคลองประเวศฯ ในการระบายน้ำลงเจ้าพระยา

ข้อมูลจริง 28 ก.ย. 69 12:38 น. สี่เขต 42 จุด: **ใกล้ล้นตลิ่ง 7 · เฝ้าระวัง 10 · ปกติ 19 · ไม่มีข้อมูลตลิ่ง 2 · ขัดข้อง 4**
(ถ้าใช้เกณฑ์ของ กทม. จะเป็น "วิกฤต" 22 จุด)

## แหล่งข้อมูล

| แหล่ง | Endpoint | ใช้ทำอะไร |
|---|---|---|
| สำนักการระบายน้ำ กทม. | `POST weather.bangkok.go.th/water/PageMap/GoogleMap` | ระดับน้ำคลองกว่า 300 จุด พร้อมเกณฑ์เตือนภัย/วิกฤต สถานะ พิกัด และระดับเปิดบานประตู |
| สำนักการระบายน้ำ กทม. | `GET weather.bangkok.go.th/Station/Map/GetData?id=0` | สถานีสูบน้ำ ระดับน้ำหน้าสถานี และจำนวนเครื่องสูบที่ทำงาน |
| สสน. ThaiWater (ยังไม่ได้ใช้) | `api-v3.thaiwater.net/.../waterlevel_load` | ระดับน้ำทั่วประเทศ แต่ในกทม.มีเพียง ~9 สถานี |

endpoint ของ กทม. เป็น API ภายในที่หน้าแผนที่สาธารณะเรียกใช้ ไม่ใช่ API ที่เปิดอย่างเป็นทางการ
จึงอาจเปลี่ยนได้โดยไม่แจ้ง ระบบจึงดึงข้อมูลแค่ทุก 5 นาทีเพื่อไม่ให้เป็นภาระเซิร์ฟเวอร์

## การแจ้งเตือน

| ประเภท | เงื่อนไข |
|---|---|
| 🌊 สรุปสถานการณ์ | ส่งครั้งเดียวตอนเริ่มระบบ หากมีจุดที่อยู่ระดับเตือนภัยหรือวิกฤต |
| 🔺 ยกระดับ | ระดับขึ้น เช่น ปกติ → เฝ้าระวัง หรือ เฝ้าระวัง → ใกล้ล้นตลิ่ง (ตามระยะห่างตลิ่ง) |
| 🔻 คลี่คลาย | สถานะลดลง |
| ⚠️ น้ำขึ้นเร็ว | ระดับน้ำขึ้นอย่างน้อย 10 ซม. ภายใน 60 นาที (ปรับได้) แจ้งซ้ำที่จุดเดิมได้ทุก 2 ชม. |

เซนเซอร์ที่ขาดการเชื่อมต่อเกิน 60 นาที หรือจุดที่ไม่มีข้อมูลตลิ่ง จะไม่ทำให้เกิดการแจ้งเตือนหลอก
พอเซนเซอร์กลับมา ระบบจะเทียบกับสถานะล่าสุดก่อนขาดหาย

## วิธีใช้

ต้องใช้ Node.js 22 ขึ้นไป และไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
cp .env.example .env      # ใส่ช่องทางแจ้งเตือนที่ต้องการ
npm start                 # ดึงข้อมูลทุก 5 นาที + แดชบอร์ดที่ http://localhost:3000
npm run once              # ดึงหนึ่งรอบแล้วจบ (ใช้กับ cron / GitHub Actions)
npm test
```

วิธีรับแจ้งเตือนบนมือถือที่ง่ายที่สุดคือ **ntfy**:

1. ติดตั้งแอป ntfy (iOS/Android)
2. Subscribe หัวข้อที่ตั้งชื่อเดายาก เช่น `bkk-flood-prawet-8f3k2`
3. ใส่ชื่อหัวข้อนั้นใน `NTFY_TOPIC=`

ถ้าเลือก LINE ให้ใช้ Messaging API (LINE Notify ปิดบริการไปแล้ว): สร้าง Official Account แล้วใส่
`LINE_CHANNEL_ACCESS_TOKEN` กับ `LINE_TO` (userId หรือ groupId)

## แผนพัฒนาต่อ

1. **ย้ายเครื่องดึงข้อมูลไปคอมที่เปิดตลอด**: ดูหัวข้อ "การ deploy" ด้านล่าง
2. **แจ้งเตือนตามที่อยู่**: ต่อยอดจาก `?near=` ให้แจ้งเตือนเฉพาะจุดวัดในรัศมี 2 กม.
3. **LINE Bot แบบถาม-ตอบ**: พิมพ์ "ประเวศ" แล้วได้สรุประดับน้ำกลับทันที
4. **รวมข้อมูลฝน**: เพิ่มปริมาณฝน 1 ชม./24 ชม. จาก กทม. และเรดาร์ เพื่อเตือนล่วงหน้าก่อนน้ำขึ้น
5. **จุดน้ำท่วมถนน**: เพิ่มข้อมูล `/Flood/PageMap/GetData` (เซนเซอร์น้ำท่วมถนน) และแจ้งเส้นทางที่ควรเลี่ยง
6. **ThaiWater / กรมชลฯ**: เพิ่มเป็นแหล่งสำรอง และติดตามระดับน้ำเจ้าพระยา/น้ำทะเลหนุน

## การ deploy (GitHub Actions + Pages)

`.github/workflows/poll.yml` ดึงข้อมูล เก็บ state ไว้ที่ branch `data` แล้ว deploy หน้าเว็บขึ้น GitHub Pages
workflow นี้ไม่ได้ใช้ `schedule:` ของ GitHub เพราะรันไม่สม่ำเสมอ (ตอนทดสอบไม่รันเลยแม้แต่ครั้งเดียวใน 1.5 ชม.)
แต่ให้เครื่อง runner สั่งรันเองทุก 5 นาทีด้วย launchd:

```bash
sed "s|SCRIPT_PATH|$PWD/scripts/trigger-poll.sh|" scripts/th.bkk-flood-watch.trigger.plist \
  > ~/Library/LaunchAgents/th.bkk-flood-watch.trigger.plist
launchctl load ~/Library/LaunchAgents/th.bkk-flood-watch.trigger.plist
# เลิกใช้: launchctl unload ~/Library/LaunchAgents/th.bkk-flood-watch.trigger.plist
```


ต้องรันบน **self-hosted runner ที่อยู่ในไทย** (label `bkk`) เพราะเว็บ กทม. ไม่ตอบ IP ต่างประเทศ
และเครื่องนั้นต้องมี `gtar` (macOS: `brew install gnu-tar`)

ตอนนี้ runner อยู่บน MacBook ของผู้ดูแล: ถ้าพับจอหรือปิดเครื่อง หน้าเว็บจะหยุดอัปเดต (มีแถบเตือนบนหน้าเว็บ)
แผนคือย้ายไปคอมที่ออฟฟิศที่เปิดตลอด: ติดตั้ง runner ตาม Settings → Actions → Runners → New self-hosted runner
ใส่ label `bkk` แล้วลบ runner เดิมออก

> ข้อมูลนี้ใช้ประกอบการตัดสินใจเท่านั้น ให้ยึดประกาศทางการของ กทม. (@BKK_BEST, สายด่วน 1555) เป็นหลัก
